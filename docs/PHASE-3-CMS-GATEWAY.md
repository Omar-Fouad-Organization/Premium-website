# Phase 3 CMS gateway — website companion change

This branch targets website main at 080ea485b41f034d733f467981aa73ec17b8a6e9 and depends on ERP Phase 3 targeting its Phase 2 authorization branch. Both changes remain draft; no merge/deployment/operational migration is authorized by this delivery.

## Boundary and contract

The public website retains its React design, routes, English/Arabic behavior, UUID CMS rows and public assets. ERP owns employee authentication, action permissions and integer exhibition membership. Website MySQL remains the content authority. No user/session/job/business-table consolidation or administrator impersonation occurs. Only an additive migration creates cms_delegation_nonces and cms_gateway_audits. The previous application ignores those tables, allowing schema-first staging deployment.

POST /api/internal/cms/{site}/{resource} is stateless. X-Space-Delegation carries base64url JSON claims; X-Space-Signature is HMAC-SHA256 of that exact encoded value. Claims bind version, issuer/service, audience, key ID, site, reviewed integer exhibition ID, ERP actor, method, full path/query, body SHA256, nonce, correlation UUID and permitted actions. Expiry is at most 30 seconds. Atomic nonce insertion rejects replay. The website independently checks the configured binding, resource/action/view and publication permissions. Unknown tables, fields, orders and broad writes are refused. JSON bodies must have a fixed Content-Length and are bounded before the framework reads them.

The identical ERP/website config/cms-contract.json catalogs twelve resource boundaries: general settings, SEO, branding, location, language settings, content, packages, FAQs, translations, media/photos, blogs and partners. Each mutation targets one row or complete unique identity. _version is a canonical row hash checked under a row lock. Successful row changes and audit entries commit together. Original multi-row ERP editors still save sequentially; they explicitly report partial or uncertain failures and never blindly retry writes.

Uploads accept actual validated bounded JPEG/PNG/WebP/GIF/ICO images in fixed public buckets and generate UUID filenames. SVG is rejected. Referenced asset cleanup checks decoded fixed CMS fields; ERP record deletion retains physical assets. Do not run internal physical cleanup while editorial writers are active: use a separately reviewed quiescent maintenance window, drain in-flight requests, and preserve backups. Orphan uploads are retained for reconciliation rather than automatically deleted. Public image routes stream only allowlisted bucket/extension paths with nosniff. Storage/CDN behavior requires production-like staging verification.

Public reads always hide private/unknown settings, inactive resources, draft and future-dated blog posts, including with an administrator cookie. Public and delegated blog HTML is sanitized without rewriting historical data. Legacy unsafe URLs and non-Google map embeds are masked on read. New writes validate map coordinates and HSL/hex colors. The explicit legacy-admin read endpoint remains; legacy CMS writes/uploads are fenced when the gateway is enabled. Contact submissions, visitor registrations and administrator-user administration are outside this gateway and unchanged.

## Configuration and release

CMS_GATEWAY_ENABLED defaults false; CMS_ERP_EXHIBITION_ID and CMS_GATEWAY_KEY have no operational defaults. Configure the same strong backend-only service secret/key ID and reviewed exhibition ID on both apps, while keeping their Laravel application keys and session stores separate. ERP also configures exact HTTPS public origin and gateway URL. Never expose the service secret through Vite, frontend code, CI operational credentials, logs or browser storage.

CMS_PUBLIC_BINDINGS_ENABLED defaults false. It gates historically unused public color settings so a deployment cannot unexpectedly restyle the existing website. Isolated browser testing verified HSL/hex bindings; that test flag was then restored off. It requires editorial/design review before operational activation. Source checks verify existing website CSS, UI primitives, header/footer and Tailwind configuration against main; none were redesigned.

Approved release order: verify deployed data/infrastructure and independent backups; rehearse in isolated staging; website additive schema first; website compatibility/security code and ERP dependent code with flags off; configure backend secrets/binding; review staff access; fence legacy writers with the website gateway; enable ERP access; perform staged UAT and public parity checks. Production deployment and actual exhibition IDs remain unverified in this local task.

Rollback disables ERP access first and reconciles correlation IDs before changing writers. Retain CMS content, UUIDs, assets and additive audit/security tables. Do not run historical rollback, reseed, restore an old database over new content or delete uploaded files. Returning to the legacy writer requires explicitly disabling the gateway after all in-flight writes drain. Retain public HTML/settings safety patches where possible. Do not run old and new writers simultaneously.

Run the bounded cms:prune-nonces maintenance command only after its schema exists, on an approved schedule. It removes at most 5,000 tokens expired more than five minutes ago and retains content/audits. Monitor authentication failures, conflicts, storage errors, clock synchronization and audit growth without logging tokens. Per-request revocation cannot cancel an already issued/in-flight delegation; its lifetime is bounded to 30 seconds.
